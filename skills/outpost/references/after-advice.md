# After Advice Workflow

Use this after receiving a response from the external consultant.

1. Match the reply to the originating outcome. A supported correction to the
   sender's subquestion is relevant; discard genuinely unrelated output.
2. Separate observations, inferred causes and proposed remedies. Verify the claims
   that can change the next action against source, runtime or current primary evidence.
3. Choose a proportionate next step: retain the approach, make a local correction,
   compare or replace methods, abandon a refuted method, or seek missing evidence.
   When one repair breaks another requirement, resolve the coupled choice before
   treating each finding as the next patch instruction. Proceed only within current
   authority; advice is not implementation or expanded-scope approval.
4. Check the changed claim or behavior. State which part the evidence covers; a
   component check is not proof that the whole approach serves the user's outcome.
5. Report the decision, useful evidence and remaining choice. Keep rejected remedies
   distinct from refuted observations, and detail in the existing result artifact.

Accepted user and compatibility constraints bind. Current code describes what exists,
not what must remain; passing tests establish only the properties they measure. When
a criterion or instrument is challenged, inspect the counter-evidence independently.
Required checks remain binding until changed by their proper authority.

## After Code Artifacts

When ChatGPT returns a zip through code mode:

1. Verify the archive opens and passes an integrity check.
2. Inspect its contents and diff manually after unpacking into a temporary directory.
3. Apply only the parts that fit the repo and user scope.
4. Run the relevant local tests before reporting completion.

Never apply a generated zip wholesale without review.
