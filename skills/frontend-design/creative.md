# Creative Frontend Design

Use this guide for an expressive landing page, hero, campaign, portfolio, or showcase. The goal is a clear point of view that serves the message, not novelty for its own sake.

## Establish the Direction

Read the project brief, existing visual system, real content, supplied references, and available assets. Before implementation, decide:

- the audience and the single message the page should land;
- one visual idea worth remembering;
- which existing brand and product constraints remain fixed.

When evidence is thin, choose one coherent direction as a hypothesis. Do not force the user through a menu of aesthetics unless the choice materially changes the product.

## Preserve Design Choice

Typography, color, composition, imagery, motion, density, and symmetry are choices, not universal rules.

- Familiar layouts, system fonts, restrained palettes, symmetry, and minimal motion are valid when they fit the message.
- Custom type, asymmetry, overlap, texture, dramatic color, or elaborate motion are valid when the brief and assets support them.
- Prefer one authored idea carried through the page over a collection of fashionable effects.
- Let real content and imagery create specificity. Do not add decoration merely to avoid an "AI look."
- Match implementation complexity to the value of the visual idea and its performance and accessibility cost.

## Finish the Actual Page

Build the usable experience, not a visual specimen. Preserve content hierarchy, navigation, calls to action, responsive behavior, semantics, and reduced-motion support.

Write visible copy for the page's audience. Convert the brief into finished messaging rather than displaying the user's request, design rationale, production notes, prompts, or tool/model choices, unless the page is meant to present them.

Inspect the rendered result at the intended desktop and mobile viewports. Revise after checking:

- whether the intended message lands in the first viewport;
- whether the memorable idea survives without obscuring the product;
- text overflow, focus, contrast, loading, and interaction states;
- motion and media performance;
- whether the result feels specific to this brief rather than generically "creative."

Project-local `DESIGN.md`, design tokens, and explicit user direction outrank this guide. A redesign request may reopen visual choices, but it does not silently discard product identity or platform constraints.
