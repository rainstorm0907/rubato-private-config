## 한 일

**6월 — 친구 모임 지도앨범으로 시작.** “지도 위에 쌓이는 친구 모임 앨범”, 셋로그처럼 10~20대 친구끼리 부담 없이 같이 기록하는 앱을 노렸다. SwiftUI + 네이버 지도로 장소 검색 → 첫 라벨, 사진을 고르면 지난 모임이 지도에 생기는 루프와 사진 핀까지 만들었다.

**7월 — 모임 앱을 크게 키움.** 7/12에 결정 등록부를 만들었다: 기존 갤러리 사진으로 지난 추억을 바로 지도에, 공개 기능 없음(참여자 기본·친구 공개 선택), 사진 내용 인식 없이 GPS·촬영 시각만. 지도·친구·앨범·프로필 4탭, 사진 수에 따른 1·2·3장 핀, 대표 한 장만 고르는 표지 부채(hand fan), 같은 날 여러 모임 나누기 보조, 로컬 앨범을 만들었다. Supabase·카카오 로그인·계정 활성화·메타데이터 백업·연락처 없는 친구 초대·모임 초대·사진 반응·계정 삭제 유예까지 올렸고, 접근성(AX5·VoiceOver)도 통과했다. Recap 카드 시안과 7/19의 Recap 시안 다섯 개는 “전부 탈락”(메인 지도와 너무 비슷함). 7/18에 사진 서버 업로드·Apple 로그인·앱 이름 변경을 잠갔다.

**8/30 — 방향 전환.** ‘모임’이 아니라 ‘장면’: 이미 찍은 개인 사진을 전국 지도에 펼쳐 보고 장소와 기억을 발견하는 개인 기억 지도(private-first)로 바꿨다. 소셜은 뒤로 미뤘다. 새 타깃 `MaplogV2`에서 실제 사진 지도, 장소·방문(Place·Visit), 촬영지 시간대 계산을 다시 지었다. 9/2엔 에이전트가 곁다리로 만든 갤러리식 화면을 보고 ‘결과부터 보여 주는’ 방향으로 틀었다. 9/3 Recap 시제품 셋을 같은 사진으로 비교해 A안(컷 없이 지도를 따라가며 도착하면 사진 카드, 촬영 시각·장소 캡션, 무음)을 골랐고, 같은 날 “메인 지도는 장소 먼저, 열면 날짜별”과 장소 합치기·나누기 승계 규칙을 정했다.

**9/10~22 — Recap 재생을 다듬음.** 약 6년·2,862장 첫 체험에서 “와리가리하는 재미”를 확인했다. 기기 안 Apple Vision 미감·유사도로 사진을 자동으로 고르고, 같은 크기 두 장·부분 겹침, 지나온 곳 다시 둘러보기(“52–57초가 제일 맘에 들었어”)를 얻었다. 9/19 오픈소스 타임라인 카메라를 통째로 옮긴 세 판은 모두 기각됐고, 9/21 본체 `MaplogV2/Recap`에 재생을 새로 짓기로 했다(목표 70점 → 90점). 9/22 핀에서 사진이 이어져 나오는 A와 거리별 속도를 합친 127초 전체편에 “이정도면 만족”을 받아 임시 v1으로 삼았다.

**9/23~27 — Recap을 앱으로.** Recap은 기간으로 시작하고 사진핀은 갤러리 역할만 하기로 했다. 모음 화면은 가/나 시제품과 여러 번의 실패 뒤 HTML 견본 1~11판으로 정했다: 계절 콜라주 + 달 띠, 틈 사이 흐린 지도, 손을 떼면 여섯 장이 제 핀으로 내려앉는 예고. 재생바도 견본 1~10판으로 정해 앱에 옮겼다(선 끌기·10초·장소 넘기기·멈추고 둘러보기·배속). 실용 사진(캡처·영수증·서류) 빼기, 기기 안 행정동 이름, 메인 지도 첫 핀 6~8초 → 약 1.3초, 입구와 빈 순간(사진 1장 기간, 분석 중, 지도 타일 대기, 새 사진 조용히 반영)을 넣었다.

**9/28 — 출시 준비.** 목표를 앱 전체 출시로 정했다: 계정·서버 없는 개인 앱, 스토어 전에 지인 폰에 TestFlight. 앨범에서 영상으로 넘어가는 다리 V1(보이던 사진들이 핀으로 흩어지고 완성된 길이 스르르 나타남), 렉 수정 두 번, Recap을 정식 빌드에 포함, 메모리 정리를 끝냈다. 이름은 ‘비행운’으로 가는 중이고, Apple 개발자 계정·번들 ID·App Store Connect 앱·개인정보 페이지를 만들었다. 메인 지도는 한 곳 한 핀·조금만 묶기·장소 갤러리 시트·네이버 Style Editor로 조용하게 만든 지도 톤으로 바꿨고, 첫 실행·권한·설정 화면과 하단 탭바 `지도 | Recap`을 넣었다.

**9/28 밤~9/29 — 첫 TestFlight.** 이름을 ‘비행운’으로 정했다(맵로그는 셋로그·같은 이름 앱과 겹침, 영어 Contrail은 상표 충돌). 새 번들 `com.wooojin.bihengun`으로 빌드 1(임시 아이콘)과 빌드 2(최종 아이콘)를 TestFlight 내부 그룹에 올렸다. 아이콘은 AI 시안에서 방향만 얻고 한 획을 직접 그려, 알려진 색 체계 12개를 실제 Liquid Glass 렌더로 비교해 골랐다. 새 사진 조용히 붙이기, 지도 묶음 세기 3단계, 첫 실행 build-2(하늘색 카드·내 위치)를 넣었다. 친구 배포 전 감사 둘(Opus·Astra)을 따로 돌려 합쳤는데, 한곳에 사진이 몰릴 때의 장소 계산 메모리, 앱 안에 실린 개발자 사진 좌표, 처리방침과 실제 동작의 차이는 한쪽만 봤으면 놓칠 뻔했다. 따로 두던 Recap 세션은 이때부터 쓰지 않는다.

**9/29 오후~저녁 — 친구 베타 전 다듬기.** 빌드 3을 API 키로 올려 외부 ‘친구’ 그룹 베타 심사에 넣었다. TestFlight 설치본에서만 한 번 뜨는 피드백 안내 카드, 다듬기 1차(Recap 첫 진입·VoiceOver 연도·고지 머리·Recap 거절 설정 열기)를 넣었다. 가운데 카드 표면은 레퍼런스 → 시안 비교를 여러 번 돌려 정했다: App Store 스크린샷·지도 앱으로 좁힌 레퍼런스는 “부족하다”는 말을 듣고 Dribbble 등 디자인 커뮤니티로 넓혔고, 고른 번호를 그대로 옮기지 않고 공통 결을 뽑아 응용했다. 엽서안은 “안 예쁨”, 유리·그라데이션·빛번짐을 겹친 안은 “AI slop”으로 빠졌고, 흰 카드(A″)가 남았다. 첫 안내 카드는 “존재 이유가 뭔데?”라는 질문으로 역할을 다시 잡아(권한 창이 누를 때 뜨게) 설명 줄을 모두 뺐고, 위쪽 그림은 하늘 사진 → 내려다본 땅 → 지도 확대본+사진 핀으로 바뀌었다. 네이버 약관이 지도 캡처의 저장·가공을 막아 그림은 손으로 못 움직이는 실제 지도로 넣었다(반포 02c).

## 잘된 방향

- **사용자가 확인한 느낌 원칙이 기준이 됐다.** 편하게 따라가되 재미있게, 과하지 않게. 한 화면에서 읽을 정보는 최소. 사진이 주인공이고, 빈약한 선정을 연출로 덮지 않는다. 누르기 전에 무엇이 나올지 알 수 있어야 한다. 속도감은 지키고, 문제를 ‘멈추는 기능’으로 풀지 않는다. 좋아한 판은 지키고 바꿀 층만 좁게 고친다.
- **기획은 같이, 기계적인 세부는 맡기.** 리드가 빨리 굳혀 좋아한 판을 두 번 잃은 뒤 정한 방식이다. 이 뒤로 되돌리는 일이 줄었다.
- **글 배치도 먼저.** 배치와 상태별 움직임을 텍스트 도식·언제/무엇 표로 먼저 맞추자 합의가 빨라졌다(“이해가 확확되네”).
- **HTML 견본 + 스위치로 나란히 보고 번호로 고르기.** 실제 사진·좌표를 넣은 견본에서 틈 4/6/8, 콜라주 여덟 안, 버튼 a/b/c를 바꿔 보며 모음 화면 1→11판, 재생바 1→10판까지 왔다. 가장 효과가 좋았다.
- **조사 방법.** 리드 가설을 먼저 적어 고정한다 → 서로 안 보는 조사 둘(브라우저로 실물·오픈소스, GPT Pro에는 가설 없이 열린 질문) → 재료마다 “맵로그에선 → …”로 옮긴다 → 보드로 사용자에게. 재생 전 신호, 재생바, 입구, 앨범→영상 다리를 모두 이렇게 정했다.
- **실제 폰, 실제 보관함으로 보기.** 시뮬레이터엔 안 보이던 쌓임·사진 비율(세로 9:16이 69%)·렉이 폰에서 드러났다. 반대로 작은 썸네일로 판단하려던 비교는 매번 헛돌았다.
- **큰 이식은 계획부터.** 담당이 코드를 안 바꾸고 계획만 내고 → 사용자 확인 → 이식 → 폰 설치는 끝에 한 번. 계획 단계에서 재생 전 10초 대기의 원인을 찾았다.
- **있는 자료와 실물부터 연다.** 문서에 적힌 오픈소스를 사흘 안 열고, 원본 앱을 두 주 안 봤던 일에서 배웠다.
- **화면마다 하는 일부터.** 한 스타일을 모든 화면에 복사하지 않고, 그 화면이 왜 있는지와 하는 일에 맞춰 요소를 골랐다(첫 안내엔 지도 그림, 베타 안내엔 누를 버튼을 그린 폰 그림). 비교 시안은 비교할 것만 다르게 하고 배경 흐림 같은 조건은 맞췄다.
