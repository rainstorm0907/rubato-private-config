**사용자 확정, 2026-09-21.** 빠르게 길을 이어가며 확대·축소하고, 사진이 있는 지역에서는 어디를 보고 있는지 파악할 수 있게 보여준다. 지도 위 사진핀과 도착 사진 감상을 이어가고, 가끔 지도를 멀리서 넓게 보며 장소와 지나온 흔적의 관계를 만난다. 이 요소들이 한 재생 안에서 함께 작동하는 것이 기본이다. 사진마다 똑같은 순서를 반복하거나 모든 장소를 자세히 읽히게 하라는 뜻은 아니다.

### 함께 지킬 것과 아직 고르지 않은 것

- **함께 지킬 경험:** 빠른 진행의 재미, 확대·축소, 사진이 있는 지역의 위치 이해, 실제 사진핀과 한두 장 도착 감상, 지나온 흔적, 가끔 넓게 보는 지도. ‘추종 대 지역 고정’의 양자택일로 다시 정의하지 않는다. 차이를 만들려고 어느 후보에서 원하는 경험을 빼지 않는다.
- **공통 기반의 역할:** 원본 경로·사진·촬영 정보와 실제 진행을 지키고, 사진 준비·표시·실행 회차·취소·성능이 그 흐름을 깨지 않게 한다. 기획 차이가 아닌 기본 결함은 담당이 해결한다. 모든 상용 기능을 끝내야 비교할 수 있다는 선행 단계로 키우지는 않는다.
- **이번 보완에서 지킬 안정성:** “특히 기존 안정적인 부분은 크게 갈아엎지 않도록 주의하자” (2026-09-21, window `01a0c416-72b8-72b3-87a9-cf3cd7328ed0`, user item `1219b599`). 좋아진 사진 표현·끊김 보완·현행 대조군을 보호하며 현재 구조 안에서 원인을 고친다. 결함까지 동결하거나 선택한 도착 변형을 금지하는 뜻은 아니지만, 광범위 재작성으로 범위를 키우지 않는다.
- **열린 방법:** 어느 때 얼마나 가까워지고 넓어지는지, 이동·사진 등장·안정 감상·퇴장·다음 이동을 어떻게 잇는지, 무엇에 시간을 쓰는지. 현재 장면 종류·줌 수치·카메라 함수·시간표 자체를 공통 기반이라는 이유로 동결하지 않는다.
- **비교의 역할:** 같은 실제 재료로 짧지만 시작과 끝이 있는 여정을 보며 더 나은 연결 방식을 찾는다. 약20초는 비교 크기이고 후보 개수·정확한 길이는 목적이 아니다. 긴 영상 발췌나 카메라만의 시연으로 대체하지 않는다. 구체 후보·차이·손해는 사용자와 논의한 뒤 제작 범위를 정한다.
- **도착 비교에서 얻은 선호:** 빠르게 도착하며 확 확대하는 왼쪽 기존 편이, 접근 중 지역 구도를 먼저 잡는 오른쪽보다 좋았다. “왼쪽 좀 좋은데?? 괜찮다”, “오른쪽은 좀 꿀렁거리기도 하고 너무 예측이 돼서 덜재밌어” (2026-09-22, window `01a0c470-089c-74aa-a684-1cafef1bffd1`, user item `9ebcd3cf`). 이어 “확대가 반복되어서 그런거같아. 움직임 자체는 괜찮아!”라고 설명했다(user item `b20ebf2f`). 상태는 **이번 비교의 사용자 선호와 반복감에 대한 설명**이다. 곡선 자체를 다시 고칠 요구로 바꾸지 않는다. 같은 발화의 “나중에 먼거리에선 쓰던가해도 될수도?”는 활용 가능성에 대한 제안이며 장거리 전용 채택은 아니다. 정확한 적용 상황과 반복 방식은 열어 둔다. 오른쪽의 이번 표현에 대한 감상을 지역 위치 이해 전체의 기각이나 예측 불가능한 움직임의 의무로 바꾸지 않는다.
- **현재 지역편에서 얻은 기준:** 성남에서 부산으로 들어와 가까운 사진들을 보고 서울로 나오는 현행26.5초에 “부산 개좋은데??”, “이제 85점 정도??”, “확실히 더 보고싶은 느낌이 이제 생겼어”라고 평가했다. 이어 “확대도 자연스러워졌고”, “줌 아웃 정도도 지금 괜찮고”, “가속도 정도도 적당해”라고 했다(2026-09-22, window `01a0c4a7-74a7-7868-af93-afa4d1bc7f68`, user item `c26f2866`). **이번 편의 사용자 감상과 다음 보완의 보호 기준**이다. 전체 입력·Recap 기능 완료나 객관적85점으로 확대하지 않는다. 확대 연결, 줌아웃 정도, 가속감, 지역 내 사진 감상을 지킨다. 남은 아쉬움은 “장거리 이동할때 좀 느린거 말곤 없어”, “최대 속도만 늘리면 될거같아”다. 이를 모든 구간의 배속이나 카메라 전면 재설계로 바꾸지 않는다. 구체 속도·구현 방식은 아직 채택하지 않았다.
- **전체편으로 이어진 호감과 남은 디테일:** 속도 보완v2 전체편128.4초에 “아까 부산에서 좋았던 느낌이 이어지는 느낌이야”, “속도도 적당하고 카메라도 이제 과하거나 답답한게 딱히 없어”, “사진핀도 진짜 내가 딱 원하는 정도로 적당히 감안하는거 버릴거 버리고 보여줄거 보여주는?”이라고 했다. “작년을 돌아보는 느낌이 들어서 좋았어. 이제 슬슬 자랑하고 싶은정도인데!?!”라는 전체 감상을 다음 보완의 출발점으로 삼는다(2026-09-22, 같은 window, user item `89dd2f71`). **이 편에 대한 사용자 감상이며, 기능 전체 완료나 모든 구간의 무결함은 아니다.** 22초 부근 둘러보기는 “쪼금만 시간 줄이고”, “스멀스멀 조금 움직이는데 안그러게 하자”라고 요청했다. 구도를 잡은 뒤 멈춰 볼 시간을 만들되 일반 이동까지 정지시키지 않는다. 39초와1:12 출발 직전의 성급함은 실제 장면으로 원인을 가리고, “카메라쪽은 괜찮아서 애니메이션 나중에 손보면 될듯”이라는 확대·카드 등장 연결과 큰 확대의 끊김·지도 로딩은 후속으로 남긴다.
- **넓은 도착이 한 번 섞인 구성의 호감:** 두 연결 보완본의 일본 진입에 “이 변화가 더 좋은데?? 아까 초반에 우리 안 두개 비교한 느낌에서 좋은것만 빼온느낌? 딱 한번 있으니까 좋다”, “지금 상당히 괜찮음”이라고 했다(2026-09-22, window `01a0c4e7-d8cc-76c6-bf9d-66f323cb243f`, user item `6dbc6243`). 빠른 도착 위주 흐름에 넓은 지역과 핀을 먼저 보여주는 장면이 한 번 섞인 이번 구성을 좋아한 것이다. 앞선 반복적인 접근 구도에 대한 아쉬움을 모든 넓은 도착의 기각으로 쓰지 않는다. 이 호감도 모든 도착의 확대 적용이나 ‘여정당 정확히 한 번’의 규칙으로 굳히지 않는다. 현재 판본을 임시v1 기준으로 남긴다.
- **A와 합칠 거리별 속도 방향:** 가까운 이동은 거의 유지하고 멀수록 빨라지되 부산급에서 기존보다 약20% 추가 가속을 상한으로 두며, 일본급에서도 그 이상 계속 빨라지지 않는 전체편 제작을 승인했다(2026-09-22, window `01a0c70d-280e-7098-b683-d0245d21ee74`, user item `db08ee11`). 앞선 “v1에서 멀어질수록 조금만 빨라지면”, “내 부산정도의 거리가 한도고 일본도 똑같이”를 리드가 구체화한 방향이다. 사진 감상을 포함한 일괄 배속이나 모든 이동시간20% 단축을 뜻하지 않는다. 구체 곡선과 시간 배분은 구현 판단이며, A의 핀 연결·안정 감상·좋아한 카메라 공간 관계를 지킨다. 실행 범위·상한은 CURRENT를 따른다.
- **지역 통과의 후속 논의:** 사진이 많은 동네를 지나는 동안의 움직임은 도착 비교 뒤 따로 의논하기로 했다. 사용자 원문: “이거 비교해보고 싶어! 사진이 많은 동네를 지나가는 동안의 움직임은 다음 단계에서 의논해봦” (2026-09-21, window `01a0c416-72b8-72b3-87a9-cf3cd7328ed0`, user item `7d85d8ec`). 이후 위 현행 지역편·전체편을 좋아한 감상을 우선한다. 새 지역 통과 연출을 예정된 다음 단계라는 이유로 만들지 않는다. 실행·담당 승인 상태는 CURRENT를 따른다.
- **이미 있는 표현과 새 제안을 구별:** ‘가끔 작게’는 지도 줌아웃이다. 사진을 작게 보여주는 새 형태나 핀에서 큰 사진으로 날아오는 새 애니메이션의 필수 도입을 뜻하지 않는다. 기존 사진핀·도착 감상을 출발 자산으로 삼으며 필요하다면 새 표현도 이유와 함께 논의한다.
- **멈추는 기능으로 풀지 않는다:** 긴 Recap에서 더 보고 싶은 마음이나 빠진 여행은 “직관적으로 '멈추는 기능 만들기'로 해결하면 절대 안될 문제”다(9/10). 재생바의 멈춤·둘러보기는 조작이지 이 문제의 해법이 아니다.

### 연결을 구현하고 판단하는 기준

기존 입력·선정·실제 경로·Naver 지도·사진 준비·기록을 재사용한다. 시야와 시간의 계획을 같은 재생 시각이 소비하고 카메라 출력은 하나가 소유한다. 새 엔진이나 별도 연출 프레임워크가 목표가 아니다.

- 시야는 실제 감상 영역·사진 지점·길·로고·조작부를 함께 고려한다. 감상, 지역 이동, 먼 이동, 다시 둘러보기는 보여줄 대상이 다르다. 필요한 시야와 시간의 관계를 조정하며 모든 정차를 동네 단위로 확대하는 새 규칙도 만들지 않는다.
- 일반 이동은 속도를 이어가고 실제 정차·취소·재시작에서 상태를 정리한다. 사진이 완전히 펼쳐졌을 때 지도도 안정돼야 한다. 준비된 장수와 표시 일정도 함께 정한다.
- 두 장의 0.32초 등장·2.60초 안정 감상·0.40초 퇴장은 좋아한 3.32초 미리보기의 출발 구성이다. 총시간만 유지하고 안정 감상을 줄이는 것은 같은 경험이 아니다. 한 장의 0.34/1.00/0.24초, 추종0.35초, 줌 제한1.2/2.0레벨/초, 약80% 속도·1.10배 강조 등은 리드의 구현 가설이며 사용자 고정값이 아니다. 현재 코드의 다른 수치도 마찬가지다.
- 원사진·촬영 시각·좌표·경로 순서를 보호한다. 특정 입력에서 나온 장수나 사진 ID를 모든 입력의 정답으로 고정하지 않는다. 한 경로의 번호를 사진 ID 목록으로 바꾸는 것만으로 일반화했다고 하지 않는다.
- 실제 한 연결과 전체 흐름을 함께 본다. 필요한 희소·밀집·혼합 입력, 사진 준비 실패·취소·재시작을 확인하고 소스·설치본·영상·실행 입력의 대응을 남긴다. 어떤 버전에서 한 검사를 다른 버전의 실제 실행으로 세지 않는다.

## 무엇을 위한 앱인가

이미 찍어 둔 개인 사진을 실제 지도에서 둘러보며 장소와 기억을 발견하는 private-first 개인 기억 지도다. 방문을 골라 이름 있는 여정으로 다시 보는 것은 기능 구상이며, 모든 감상의 필수 도착점이 아니다. 새 기록을 오래 쌓거나 사진을 일일이 정리해야만 첫 가치가 생기는 제품도 아니다.

사용자는 위치 정보가 있는 개인 사진을 가진 사람이다. 현재 직접 확인한 사용자는 우진이다. 기존 사진 보관함에서 찾아 보는 행동보다 기억을 쉽게 발견하게 하고 다시 열 이유를 만드는지는 일반 사용자에게 검증하지 않았다. 누적 지도를 보러 오는지, 완성된 여정을 다시 보는지도 열린 질문이다.

9/14 사용자 원문: “아직 미완이라 그렇게 따로 보진 않는거같아. 그리고 테스트과정에서 많이 봐가지고 아직은 템플릿도 한개이고. 나중에 좀 완성되면 주변에 친한사람들한테 좀 보여줄거같아.” 미완·반복 테스트라는 조건을 보존한다. 재방문 가치의 실패로 단정하거나 템플릿 추가·지인 검증을 당장 선행시키지 않는다.

장기 목표는 상용 앱 수준과 App Store 출시다. 9/11 원문: “당장은 절대 아니지만 먼 미래의 목표는 어쨋거나 상용 어플수준의 개발, 앱스토어 출시”, “대신 신경쓰지 마. 그냥 너도 인지만 해두고 지금처럼 천천히 하나씩 만들어보고싶어”. 지금 출시 준비나 통합을 앞당기는 근거로 쓰지 않는다.

## 구현 단계와 무관하게 지킬 감성

상태: 사용자 확정(2026-09-10). 리드가 제안한 문장을 사용자가 인용하며 “이거 핵심 문서에 꼭 넣어줘”라고 요청했다.

> “얼마나 쉽게 고르나”만이 아니라, “고르지 않아도 충분히 즐겁고, 잇고 싶어졌을 때 감상이 끊기지 않나”

“잇고 싶어졌을 때”는 조건이지 방문을 잇고 싶도록 만들어야 한다는 목표가 아니다. 사용자는 익숙한 지역에 빽빽하게 쌓인 사진을 보며 만족하고, 외곽의 여행 사진을 발견하면 “아 내가 저런데도 갔었지” 하며 확대한다고 설명했다. 익숙한 지역의 만족은 당시 “방금 더 떠올랐던거야”라고 밝힌 새 발견이다.

같은 날 원문: “만약 이 제품에서 이어지는걸 관해 얘기했었다면 recap을 제외하곤 고집하지 않았으면 좋겠어”. Recap 밖 방문 연결의 필요성은 다시 살피되 여정 기능 전체의 폐기로 확대하지 않는다.

| 지킬 경험 | 피할 모습 |
| --- | --- |
| 실제 사진을 보며 장소와 기억을 발견한다. | 사진보다 수치·분류·관리 도구가 앞선다. |
| 방문을 하나도 고르지 않고 사진만 보다가 나와도 충분하다. | 감상을 제작 준비로 취급하며 계속 선택·완성을 재촉한다. |
| 잇고 싶을 때 별도 행동으로 방문을 담되 보던 기억을 잃지 않는다. | 추가·해제 때 감상이 끊기거나 지도·카메라가 초기화된다. |

화면 역할이나 주요 조작이 바뀔 때, 결과를 보여주기 전에 대조한다. 구현 검사와 에이전트 호평으로 감상 경험을 대신하지 않는다.

## 장소를 고쳐도 기억은 이어져야 한다

**사용자 확정, 2026-09-03.** 메인 지도는 장소(Place)를 먼저 보여 주고, 장소를 열면 그 안에서 촬영지 날짜별 방문(Visit)과 사진을 보여 준다(“같은 장소가 먼저고, 같은 날이 그다음”). 장소를 여는 행동과 여정에 방문을 넣는 행동은 따로다.

장소 후보의 40m 연결 거리 / 100m 전체 지름은 초기 정책이지 장소의 정체성이 아니다. 사용자가 고친 장소를 정책 변경으로 다시 묶거나 기존 장소끼리 자동 합치지 않는다.

- **합치기:** 사용자가 대상으로 고른 Place가 남고, 흡수된 Place를 가리키던 참조는 남은 쪽으로 이어진다. 같은 날짜 Visit 둘이 만나면 대상 쪽 Visit가 남는다. 여정에 둘 다 있었으면 먼저 놓인 순서를 남기고 중복을 합친다.
- **나누기:** “이 사진들을 새 장소로 분리”다. 남긴 사진 쪽이 기존 Place·Visit를 유지하고 옮긴 사진은 새 Place가 된다. Visit 사진 전체를 옮기면 Visit도 함께 옮긴다. 새 Visit를 기존 여정에 자동으로 넣지 않는다.
- **되돌리기:** 다음 사진 반영이나 교정 전까지 직전 교정 한 단계를 저장해 되돌릴 수 있다. 소속·ID 연결·여정 중복 변화와 되돌리기 기록은 한 번의 저장으로 함께 다룬다.
- **화면은 미정:** 버튼·별도 기능·메인 지도 끌기는 비교할 후보다(“그 합치고 나누는 ux 가 매우 중요할것으로 생각된다”). 기능의 존재보다 발견성, 조작 중 잘못 합칠 위험, 결과 이해, 즉시 피드백과 되돌리기가 중요하다. 반려한 큰 합치기 행동을 메인 감상 화면에 되살리지 않는다.

나중이라는 말로 자동 재개하지 않는다. 되살리려면 사용자와 다시 정한다.

- **전체 공개 없음.** 공개 피드·공개 지도는 제품 범위 밖이다. 공유·협업·소셜은 개인 가치 뒤다.
- **계정·서버 없음.** 카카오·Apple 로그인, Supabase·R2 서버, 백업·기기 간 복원, 친구·모임·초대·반응(옛 앱 `code/Maplog`)은 이번 출시에 넣지 않는다. Apple 로그인을 다시 열 때는 Debug에서 비운 `CODE_SIGN_ENTITLEMENTS`를 `Maplog/Maplog.entitlements`로 되돌려야 한다(안 그러면 켜도 조용히 실패).
- **LLM·서버 사진 분석 없음.** 사진 내용은 기기 안 Apple Vision(미감·유사도·실용 사진 구분)으로만 보고, 그것도 Recap 사진 고르기에만 쓴다. 장소·방문 묶기는 위치·촬영 시각만 쓴다.
- **사진 가져오기에서 장수 제한·성능 모드 팝업 없음.** 앱 안에서 알아서 가볍게 처리한다. 표지를 다시 만들더라도 사용자는 대표 한 장만 고르고 나머지는 자동이다.
- **확대하면 세로로 길어지는 사진핀은 되살리지 않는다**(9/28 폰에서 어색해 뺌, `e7bb8f9b`).
- **새 사진 발견 알림 — 아이디어로만 보존(2026-09-10).** 원문: “어플 새로 켰는데 새로운 사진 탐지되면 팝업>애니메이션>해당 위치로 이동 같은 이펙트 넣으면 재밌을거같아. 뭐 사진 작게 띄우고 새로운 사진을 찾았어요! 하고 버튼 이동 / 닫기 이런식. 지금 하자는건 아니었어 대신 기록해줘.” 새 사진 반영 자체는 출시 전에 필요하다(팝업 없이 조용히 붙이는 방향, 위 결정). 팝업·이동의 순서·빈도·자동 이동 여부는 미정이며, 강제 팝업이나 자동 이동을 확정한 것으로 읽지 않는다. 새 사진 반영을 다시 설계할 때 원문과 실제 사진을 함께 보고 판단한다.

## 아직 정하지 않은 것

- Recap의 볼거리 기반 속도 배분, 중거리 시야와 지역 둘러보기, 미래 정차 사진핀의 크기·노출 범위, 공통 틀 완화 수치와 전체 감상·최종 채택.
- 사진 선정에서 미감·반복·놓치는 기억의 균형과 다른 보관함의 충분함. iPhone 기기 내 미감 분석·본체 통합은 이번 밖이다.
- 새 혼합 방향 형태와 세 장은 한·두 장 재생 뒤 별도 논의한다. 기존 최대 세 장의 가능성을 영구 폐기하지 않는다.
- 사진 날짜·좌표 변경의 자동 이동/확인, 거절한 장소 검토의 재등장, 다른 ID로 재등록된 사진의 복구.
- 합치기·나누기의 진입·조작·피드백, 새 사진 반영과 되돌리기, 하루 장면·장소별 장면의 표현, 저장 목록 위치·이름.
- 지역·사진 묶음의 발견과 감상 방식, Recap 탭과 갤러리 개편의 디테일([지도 갤러리와 기간 Recap](#app-shape-2026-09-23)), 다음 구체 제작 범위. 발견 알림은 위 [안 하는 것](#not-this-release)에 아이디어로 보존한다. 직접 고른 기간의 자리와 “+” 입력(9/30 사용자 “기간 편하게 선택해서 수동으로 볼 수 있는 기능도 필요한거같아. 지금 너무 기능이 정해진대로만 사용돼서 살짝 불편”, `e76bb8fb`. 이어 “3번 기능을 좀 메인으로 해볼까? 지금 좀 살작 난잡한감있어서”, `f2df3a44` — 기간 직접 고르기를 Recap 탭의 주 기능으로 비추는 방법을 의논 중. 같은 대화에서 알약은 `해 | 계절 | 월` 세 칸으로 하기로 함: 해 화면을 열어도 `계절`이 눌린 채라 헷갈리고 “1년 리캡도 살짝 숨겨진 느낌”이라서), 재생 지도의 색, 갤러리에서 “지금 보고 있는 사진들 영상으로 볼까요?” 팝업의 모양도 미정이다.
