# Maplog V2 재시작 왕복 실기기 피드백

날짜: 2026-09-02
맥락: 실제 iPhone 14에서 실제 PhotoKit 사진 188장을 7개 persisted capture-day occurrence로 만들고, Journey 3개를 저장한 뒤 강제 종료·아이콘 재실행을 검증함.

## 사용자 확인 — 검증됨

우진:

> “첫 Journey 날짜 근처 카메라가 맞고, Journey 3개와 1·2·3 번호도 잘 돼.”

같은 occurrence store가 재실행 뒤 7 occurrence·188 assignment·Journey order 3개로 복원됐고, 사용자가 화면의 순서·번호·첫 카메라를 직접 확인했다.

## 제품 피드백 — 사용자 관찰

우진:

> “일단 여정 날짜 단위로 나눈거 좋은데, 지금 보니까 거리가 너무 먼거까지 되니까 살짝 당황스러웠어. 왜냐면 아직 사진은 날짜별이 아니라 그냥 전부 나열되어있어서 그런거같아.”
>
> “자연스러워지려면 나중에 하기로 하긴했지만 그거 있잖아. 사진도 날짜 단위로 묶어서 갤러리 식으로 볼 수 있고, 클러스터도 전에 피드백 받은대로 수정해보면 괜찮을 수도 있을거같아.”
>
> “근데 지금처럼 2가 두개로 중복처럼 보이는건 혼란이라 좀 확실히 정할 문제인거같아.”
>
> “클러스터는 아직 여전히 변동적으로 발동중인거 확인했어.”

상태:

- 날짜 단위 Journey 방향: 사용자 긍정 확인.
- 날짜별 갤러리와 고정 날짜 카드 표현: 아직 구현하지 않음. 기존 [[decisions/maplog-v2-date-scene-groups.md]] 계약을 후속에서 구현해야 함.
- 같은 Journey 번호가 여러 member 사진에 반복되는 표현: 사용자 혼란 확인. 정확한 해결 표현은 사용자 확인 대기.
- 확대율마다 대표·소속·개수가 바뀌는 cluster: 이전 반려 상태가 그대로임을 재확인. 이번 재시작 체크포인트에서는 renderer를 잠가 수정하지 않았음.

## 리드 책임 기록

재시작 구현 브리프가 persisted occurrence 번호를 모든 member marker에 투영하도록 요구해 중복 번호를 만들었다. 저장·복원 correctness와 별개로 한 날짜 occurrence가 화면에서 하나의 Journey 노드로 읽히지 않는 실패이며, 리드가 체크포인트 설계에서 놓친 항목이다.
