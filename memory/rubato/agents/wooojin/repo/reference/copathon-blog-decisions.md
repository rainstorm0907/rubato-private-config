## 2026-09-02 코파톤 후기 공개 범위

- 상태: 사용자 확정.
- 맥락: 코파톤 현장 경험을 개발일지 후기용으로 장면별 복기하는 중.
- 우진 원문: “그날 밤 사라진 결과물을 찾으려고 노트북 캐시까지 뒤진 순간 이거 페이블이 말한건 이거 글에 남기면 안돼. 결과물이 내 노트북에 있다는거잖아”
- 결정: 노트북 캐시에서 결과물을 복구하려 했던 장면은 공개 글에서 완전히 제외한다. 글이 결과물이나 주최 측 비공개 자료가 우진의 노트북에 남아 있었다는 인상을 주지 않게 한다.

## 질문 답변 작성 주체와 외부 AI 사용 여부

- 상태: 사용자 확정.
- 우진 원문: “그냥 생략해줘”
- 결정: 3분 질문에서 답변을 누가 작성했는지, 외부 AI를 참고했는지, 질문 화면을 별도 세션에 보낸 이유는 공개 글에서 전부 생략한다. 확인되지 않은 ‘직접 작성했다’는 주장도 넣지 않는다.

## 다른 참가자의 발언

- 상태: 사용자 확정.
- 우진 원문: “옆자리 사람이랑은 ‘내 생각대로 잘 안됐다’ 라고 하셨는데 이건 글에 적으면 안될듯”
- 결정: 옆자리 참가자가 자신의 결과를 평가한 발언은 공개 글에서 제외한다. 참가자를 특정하거나 타인의 성과를 대신 평가하지 않는다. 현장 전체가 머쓱하고 지쳐 보였다는 우진 자신의 인상만 익명 분위기 묘사로 사용할 수 있다.

## 실력으로 강조할 것과 제외할 것

- 상태: 사용자 확정.
- 우진 원문: “내가 예습문제를 직접 만들어서 probe 세팅을 체험해보고, 비슷한 환경 조건과 문서를 가지고 여러번, 그리고 결과까지 만들어본 그 연습이 정말 소중하고 critical 했던거같아.”
- 결정: 단순 도구 숙련보다 실제 환경과 닮은 모의 문제를 직접 만들고, 같은 조건·문서·제출 결과까지 여러 번 완주한 연습을 핵심 실력과 준비 과정으로 강조한다.
- 우진 원문: “‘Sol은 방향을 잡는 역할, Fable은 구현하는 역할로 나눴어.’ 이거는 다른사람들도 한다고 생각해서 제외해줘.”
- 결정: Sol/Fable 역할 분담 자체는 차별적인 강점이나 핵심 교훈으로 강조하지 않는다. 필요하면 사실 설명에만 최소한으로 남기고, 글의 주장에서는 제외한다.

## 현장을 나설 때와 다시 한다면

- 상태: 사용자 확정.
- 들어갈 때는 낯선 장소가 신기하고 긴장됐으며, 최상의 컨디션으로 할 수 있는 최대를 하고 싶었다. 나올 때는 모든 일이 하루 만에 벌어졌다는 사실이 실감 나지 않고 이질적으로 느껴졌다.
- 다시 한다면 방향 판단과 구현의 연결을 더 직접적이고 부드럽게 만들고, 구현 범위를 더 일찍 줄인다. 먼저 작은 범위라도 직접 피드백이 들어간 좋은 결과물을 완성한 뒤 기능을 확장한다.
- 후기를 읽는 사람에게 무엇을 남길지는 아직 미정이며, 사용자가 더 고민한 뒤 확정한다.
