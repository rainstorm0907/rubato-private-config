## 실행 계약

현재 단계의 제품 실패를 쉬운 말로 정의하고 완료 증거·쓰기 범위를 정한다. 구현은 Grok xhigh 수준으로 진행하고 테스트·실기기·스크린샷 현물을 회수한다. 구현자 판단과 분리한 독립 검토를 받아 제품 계약과 비교한다. 명백한 구현 결함은 같은 단계에서 최소 수정하고 재검증한다. 제품 감성·트레이드오프·방향 선택이 필요하면 임의로 정하지 않고 우진에게 가져간다. 단계가 끝나면 짧은 브리프를 쓰고 멈추며, 우진의 다음 단계 승인을 기다린다.

반드시 멈추는 경계: 단계 완료, 제품 방향 변경, 사람 체감 판정 필요, 기존 합의를 바꾸는 추측 필요, 비가역·교차 작업 침범, 같은 접근의 두 번째 실패.

사용자 표현은 작업 티켓이 아니라 제품 의도로 읽는다. `뭔가 별로`, `우수수`, `팟 팟 팟`, `감성 무너지는 거 아냐`를 관찰 가능한 화면·동작 실패로 번역한다. 좁은 테스트 PASS를 제품 PASS로 옮기지 않는다. 독립 리뷰에는 답을 유도하지 않고, 한 단어 판정은 통과 범위로 다시 번역한다. 미완·미룬 약속을 조용히 버리지 않는다. 방향 변경은 `원래 → 새 방향`과 의도를 1~2줄로 설명한다.

## 단계 종료 브리프

원래 실패, 변경, 실제 검증, 픽셀 변화, 독립 리뷰 결과, 남은 문제, 우진이 판단할 한 가지를 쉬운 말로 보고한다. 파일과 스크린샷은 절대경로로 쓴다.
