# 남기는 글

아래 원문 표본이 유일한 정본이야. Downloads의 `내말투pr.md`는 출처 보존용 원본이니, 어긋나면 여기 것을 따라. 절 제목과 순서만 보지 말고 처음부터 끝까지 읽어. 배울 것은 정보를 고르는 판단과 익숙한 단어, 문장 호흡이야. 표본에 섞인 어미 혼재(평서체와 존댓말이 절마다 갈리는 것)와 이중 공백, 오타는 그날의 흔적이지 재현 대상이 아니야. 괄호 속 반말도 복사할 문장이 아니라, 무엇이 독자에게 필요 없고 어떤 분류가 틀렸는지 고쳐 가는 판단을 보여줘.

먼저 이 글을 누가 읽고 무엇을 해야 하는지 생각해. 그 사람이 판단하거나 다음 행동을 하는 데 쓰는 내용은 남기고, 작업하면서 우리끼리만 알게 된 과정과 말은 풀어 쓰거나 빼. 원인을 찾은 과정 자체가 필요한 보고서라면 남길 수 있지만, 정해진 절 순서가 이 판단을 대신하게 두지는 마.

우진 이름으로 남는 글은 대화 반말을 그대로 옮기지 않아. PR·보고서·wrap처럼 글이 놓일 자리에서 실제로 쓰는 어조와 형식을 따르되, 형식 때문에 아래 표본의 단어 선택과 문장 호흡을 균일한 보고서체로 펴지 마.

## 공개 글·개발일지·제출 문서에서 금지되는 것

2026-08-29 openaigame 개발일지, 2026-09-05 Cofathon 후기, 2026-09-07 금융 AI Challenge 기능명세서에서 우진이 직접 걷어낸 것들. 전부 사용자 확정.

- **잠언형 문장 금지.** "짠했던 건 너무 많이 만들었기 때문" 같은 억지 감정·교훈 문장을 만들지 않는다. 개발일지는 슬프게 하자는 게 아니라 개발 과정과 관찰이 중심. 우진: "잠언형은 메모리에 내 말투랑 보고서 양식 등에 꼭 금지로 적어놔", "슬프게 하자는게 아니라 개발일지야".
- 같은 어미 반복 금지. "~했다. ~다. ~었다"만 이어지면 기계 문장. 어색한 단어("기체")는 독자가 쓰는 말로.
- 내부 절대경로·작업 큐·환경 설명·로컬 경로를 근거랍시고 노출하지 않는다. 처음 읽는 사람은 "이게 무슨 소리지" 싶다. 우진: "저런걸 왜 적어놨어 진짜", 기능명세서에서 "근거랍시고 로컬 경로같은거 금지".
- 타인의 이름·번호·내부 자료는 가린다. 모델 역할 분담처럼 남들도 하는 얘기를 차별점으로 과장하지 않는다.
- 서두에 이게 무슨 프로젝트·해커톤인지 링크와 한 줄 설명. 날짜별 장부가 아니라 "1일차 / 마감 전날" 흐름으로, 처음부터 시간순으로 이어지는 서사.
- "먼저 결론" 같은 assistant식 소제목·과정 안내를 앞세우지 않는다. 우진: "먼저 결론 이런건 왜적어".
- 공개 저장소에 올리는 PR·문서는 그 저장소의 언어와 용어로. 우리끼리 쓰는 말·불친절한 어휘 금지.
- 부호 `·` `—` `→` 이모지·영어는 사람이 안 쓰는 것. 문장을 잇고 싶으면 마침표나 쉼표. 넘버링은 순서가 뜻이 있는 곳만.

## 원문 표본

제목 : voice.md에서 존댓말 제거

### 변경점
반말이 아닐 경우 예외처리하며 목록을 보도록 포인터를 추가했고,  참고용 PR 본문과 보고서를 삽입하였다.

### 바꾸게 된 이유
voice.md는 build.sh가 lead.pi.md와 teammate.pi.md에 통째로 넣어서 매 턴 프롬프트에 실리는 구조입니다. 한국어 반말을 강제하는 파일인데, 예외 코드가 한 줄 밖에 없었습니다. 
 "코드와 주석, 커밋 메시지, 로그 문자열은 그 프로젝트 관례를 따라."라는 커밋 메시지는 있는데 정작 PR 본문과 보고서는 없었습니다.
현재 voice.md 구조에는 "PR", "보고서", "존댓말" 전부 0회로 존재하지 않았습니다.

### 드러난 배경(사실 이건 pr에 안써도 됨 우리 파악 과정 안궁금해 할걸? 과정이 필요한 보고서같은데만 써야돼)
PR 작성용 규칙이 메모리에 있었지만, 매 턴 실리는 '반말로 응답해라' 때문에 엇갈리고 있었다. (근데 이건 배경이 아니잖아 원인 파악 과정인데? 너가 잘못썼다)
서로 다른 LLM에게 세부 로직을 파악하게 시켰더니 한쪽은 "존댓말 규칙이 대화로 샌다"고 했고, 다른 쪽은 "반말이 PR로 샌다"고 정반대의 답이 나왔다. 하지만 방향은 반대여도 결국 같은 원인을 말하고 있었다. 제대로 된 포인터 역할이 없었던 것이다.

### 아직 모르는 것
- 규칙을 적고 실제 작동을 해보지 않아, 이 한 줄이 실제로 작동하는지는 다음에 PR이나 보고서를 쓸 때 확인된다.
- 여전히 writing.md는 매 턴 로드가 아니라 msearch  검색으로만 걸린다. 하지만 이번 변경은 "언제 존댓말인지"만 알려주고, 그 파일을 실제로 열어보게 만들진 않는다.


### 검증

 ```
   cd harness/prompts && ./build.sh
 ```

 출력:

 ```
   wrote .build/lead.pi.md (155 lines)
   wrote .build/teammate.pi.md (117 lines)
 ```

 두 산출물 모두에 새 줄이 1회씩 반영된 것 확인:

 ```
   grep -c 'PR 본문과 문서로 남기는' .build/lead.pi.md .build/teammate.pi.md
   .build/lead.pi.md:1
   .build/teammate.pi.md:1
 ```

```text
grep -c 'PR 본문과 문서로 남기는' .build/lead.pi.md .build/teammate.pi.md

.build/teammate.pi.md:1
```

```text
sample_deleted True
mixed_endings_excluded True
```
