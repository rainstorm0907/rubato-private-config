## 살아남는 제품 결정 (사용자 확정, 다음 제품에도 적용)

- **대화는 AI, 확정은 이용자, 조립은 코드.** AI는 사실 후보만 제안하고 확정 도구가 없다. 소명서 문장은 확정 사실만으로 코드가 서식 순서로 놓는다. 우진 9/6: "사용자 발화로만 구성하게 되어있고 … 에이전트가 안붙였으면 해". 근거: 은행에 내는 문서에 AI slop 인상을 주면 안 됨.
- **서비스가 AI 완성 소명서를 주는 곳이 아니다.** 초안+빈칸+본인 수정. AI 첨삭(표현 제안)은 법 경계라 안 함. 우진 9/5: "우리가 직접 ai소명서를 제공하는 사이트는 아니야."
- **패널은 안 봐도 진행에 지장 없는 메모지**(형 관점). 진행률 숫자·남은 개수 금지, 현재 단계 표시만 허용. 우진: "패널이 사용자를 독려할지 압박할지 기존 회의가 맞아."
- **안전값 게이트는 코드가 결정적으로 검사**(재송금·인증수단 제공 확정 시 자동 조립 중단, 직접 작성은 가능, 가담 판정 아님). 빈 작성실·종결 화면 진입은 조건 없음.
- **사례 인용은 "이런 사례가 있었다"까지.** 은행 공식 답변처럼 쓰지 않고, 결과·기간 약속 없음, 낸 것과 결과 분리. 우진: "겁먹지 않게. 귀찮지도 않게. 우린 도와주는 서비스니까."
- 금지 문구: "당신은 ○○유형" / "풀려요" / "N개 남음" / "공고 기다리세요" / "소액이면" / "유리·불리" / "제7조 ○호" / "필수". 부호 `·` `—` `→` 이모지·영어 화면 노출 금지. 서비스 화면·문서 전부.
- 용어: 명의인(우리 유저, "피해자" 금지)·송금인·문제 입금·소명서(별지 제4호서식 "이의제기 사유"란). 사건 가설 A~G는 내부 분류, 화면 노출 금지.
