## When a session in the T3 app dies stuck on a "문맥 모드" approval dialog

- **Symptom**: starting a new thread as astra in the app raises `Provider turn start failed / The operation was aborted due to timeout`, and then a `문맥 모드 승인/거절` dialog remains. Every press, approve or reject, piles up `Cannot route thread '<id>' because no persisted provider binding exists`. There is no row for that thread in `provider_session_runtime` at all.
- **Shape of the deadlock**: session start confirms the mode as summary while it does not know the model → the following `set_model(astra)` `await`s a "노트 모드로 바꿀까요?" confirmation → that confirmation holds the start RPC until timeout → the binding is not saved → the answer to that confirmation has nowhere to go. **Pressing quickly does not help** (it fails even if pressed within 3 seconds). The fact that the approval dialog appeared is itself the signal that it is already late.
- **Fix**: `1fdc26e45`. If there is no recorded mode and no mode the user stated, the first model's default simply wins and no confirmation is raised. The regression test is `harness/pi-runtime/features/context-notes/new-session-astra-mode.test.mjs`.
- **Do not**: the workaround of covering it with the `RUBATO_CONTEXT_MODE=history-notes` environment variable. The confirmation dialog disappears, but every session is fixed to notes mode. On 2026-09-16 Woojin rejected it because of that side effect.
- **A thread that has once entered this state cannot be revived.** There is no binding row, so there is no handle to roll back; make a new thread.

## A running pi-server still holds the old code after an engine update

- **Symptom**: a session does not open, and T3 raises `Provider turn start failed` / `Internal server error`. What the server actually threw was `이 세션은 작업 노트 방식으로 이어져 있어요...`.
- **Trap**: `rubato remote` or an engine update changes only the disk. A `pi-server` already up (parent pid 1, `--runtime-root ~/.rubato-pi/stock-engine`) holds the modules from startup in memory, so **it judges with the old code until restart.** If the symptom is unchanged even after the fix commit is in, first compare start time and install time with `ps -o lstart= -p <pid>`.
- **How to tell**: revert the fix in the repository's regression tests and count how many fail. If the failures are only one case different from the user's symptom, the disk code already blocks that symptom, and the remaining cause is the running process.
- **Caution**: that server hosts the user's live sessions. Killing it ends conversations in progress too. Restarting the desktop app itself also drops the Tailscale Serve path (the item below), so it is cheaper to bring only the server back up.

## Where tokens go — the multiplication of a long conversation

- **Consumption is context size × call count.** One user input gets about 10 tool round-trips attached (measured on the 2026-09-15 session: 46 user turns → 481 API calls), and each of those round-trips rereads the whole context accumulated so far. One session of 478 calls was 140 million cache reads alone, and of that only 250 thousand output was actually newly made.
- **Measured by model (average read per call / maximum context reached)**: astra 135K / 253K · sol 120K / 271K · opus 205K / **643K** · fable 236K / 551K. The cache ratio is 95% on every side. **The difference is not caching performance; it is whether context is left to grow.** astra's window is 270 thousand, so it is forced down; opus's is 1 million, so it grew to 640 thousand and every call reads that.
- **`RUBATO_CONTEXT_WINDOW_TOKENS` applies only in work-notes mode.** Summary mode has no threshold setting at all (no related environment variable besides `RUBATO_SERVER_COMPACTION_DISARMED`). So the only path to press opus down is to put it in `HISTORY_NOTES_DEFAULT_MODELS` and run it in notes mode, and the compromise is that full-text reference of the original weakens. Status: on 2026-09-18 Woojin chose to go with "주제 바뀔 때 새 스레드" without this change.
- **Limits are separate per provider.** Subagents (sol/astra) use the Codex limit, lead conversation (opus/fable) uses the Claude limit, and Grok uses the xAI limit. Cumulative measured: Codex family about 3.5 billion, Claude family about 1.2 billion, Grok 160 million. **If heavy exploration and verification are given to Grok, the lead session's context does not inflate and the Claude week does not shrink either.**

## How to connect to the Mac from an iPhone

- **The official path is T3 Code.** Connect to the Mac's T3 server with the App Store T3 Code app (or Safari). It is the same server used on the desktop, so the thread continues on the phone. Source: `scripts/remote-release/USER-TEST.md` — "아이폰 클라이언트는 T3 Code다. 맥에서 `rubato-gui`로 연 환경에 T3 Connect로 붙인다."
- **The in-house PWA (`/rubato`) was retired.** The 2026-09-16 update removed the PWA and the hub's HTTP/WS layer, and the installer no longer creates a `/rubato` Serve path. An old icon left on the phone home screen falls through to `/` and gets T3's `index.html` with 200, so it looks **"연결은 됐는데 목록이 비어 있는"**. It is not broken; it is gone, so delete the icon.
- **Issuing a pairing**: `cd ~/.rubato/t3-source && T3CODE_HOME=~/.rubato/t3-home node apps/server/dist/bin.mjs pair --tailscale --ttl 2h --label <이름>`. The address, token, and QR come out together. Make the QR image with `qrencode -o <png> -s 20 -m 4 "<pairing url>"` and show it on the Mac screen or send it by Telegram.
- **Prerequisite**: the phone connects to the Mac's T3 server, so **the desktop app has to be on**. The tailnet path `/` → `127.0.0.1:3773` is claimed by the desktop app (`holdTailscaleServe` in `~/.rubato/t3-source/packages/tailscale/src/tailscale.ts`). It rechecks every 5 seconds, yields if another live backend already holds `/`, and retries while Tailscale itself is down.
- **Teardown removes only `/`.** Shutdown calls `tailscale serve --https=<port> --set-path=/ off`, and only while that handler still points at this backend's local port. Rejected: `tailscale serve --https=443 off`, which cleared every path on 443, including a route another tool had mounted beside `/` (the code comment still names a `/rubato` route). Do not "restore" a phone by laying serve paths from an old note; check `tailscale serve status` first.
- **Reboot trap — phone stuck on `reconnecting to woomac`.** macOS drops the VPN on shutdown. Tailscale records that as `stopTunnel: userInitiated` and, with `maintainCurrentState`, comes back `WantRunning=false` / `BackendState=Stopped` even though the app is a login item (`TailscaleStartOnLogin`). The phone app is fine; the Mac tunnel is down, so Serve never attaches. Both-sides restart only looked like the fix because it brought the tunnel up and then let T3 claim `/`.
- **Workaround on this Mac:** LaunchAgent `com.wooojin.tailscale-autoup` runs `/Users/wooojin/.local/bin/tailscale-autoup` at login, polls every 5 seconds for 3 minutes, and runs `tailscale up` if the backend is `Stopped`. Log: `~/Library/Logs/tailscale-autoup.log`. Side effect: turning Tailscale off within 3 minutes of login turns it back on. The root Tailscale behavior (1.102.4 when this was set) was not fixed in the app.
