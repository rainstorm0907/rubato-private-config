# OpenAI Game 구현 전 억지 방지 관문 추가 요청

우진님이 명시적으로 요청한 지속 규칙이다.

- OpenAI Game 작업에서 매 구현·위임 전 현재 단계와 허용 범위를 먼저 확인한다. 문서가 있어도 `REFERENCE`·`DRAFT`는 구현 허가가 아니다.
- 브리프에는 `현재 단계 / 판정할 가설 하나 / 근거 문서와 절`을 반드시 적는다. 셋 중 하나가 없거나 충돌하면 구현하지 않고 반려한다.
- 한 버전은 한 가설만 판정한다. 여러 새 시스템을 한 번에 묶지 않는다.
- 숨은 발견·보상은 실제 플레이에서 자연스럽게 관찰된 행동, 먼저 존재하는 맵·오브젝트의 유혹, 사후에 납득 가능한 원인, 검증된 플레이 기술 출처, 행동을 확장하는 보상을 모두 갖춘 뒤에만 구현한다.
- 구현 편의상 이미 감지 가능한 이벤트를 먼저 골라 의미를 붙이지 않는다. 항상 `억지가 아닌가`를 명시적으로 판정한다.
- Fable 독립 확인은 단계 전환, 새 시스템의 첫 도입, REFERENCE/DRAFT를 구현으로 바꾸는 경계에서 필수로 받는다. 숫자 튜닝·같은 단계 단일 변수 실험·버그 수정에는 의식적으로 남발하지 않는다.
- Fable 검토는 입력일 뿐이며 메인 세션이 문서·실제 플레이 증거와 대조하고 우진님의 범위 승인을 받은 뒤 구현한다.
- 현재 기준은 v4이며 v5 위에 다음 버전을 쌓지 않는다. 맵과 핵심 플레이가 먼저다.

## Fable·텔레그램 연결

- OpenAI Game의 Fable 독립 점검 세션은 `~/.claude/channels/telegram-2`의 기존 `@maplog_bot`(봇명 `어플개발`) 슬롯을 사용한다.
- 전역 Telegram 플러그인을 켜지 말고, 해당 세션에서만 `TELEGRAM_STATE_DIR=~/.claude/channels/telegram-2`와 Telegram channel 플러그인을 지정한다. 다른 세션이 봇을 가로채지 않게 한다.
- 판단 세션은 기본적으로 Fable medium·plan mode로 두고 구현이나 파일 수정을 하지 않는다. 구현이 필요하면 별도 승인과 브리프 관문을 거친 세션으로 넘긴다.
- 연결 확인은 Claude 프로세스 생존만으로 끝내지 않고, `mirror.last` 갱신 또는 실제 Telegram 전송 성공까지 확인한다.
- 현재 Codex 데스크톱 대화는 Claude channel 훅의 자동 미러 대상이 아니므로, 메인 세션의 단계 판정·작업 시작·완료 같은 핵심 업데이트는 같은 봇으로 직접 전송한다. 자동 연결됐다고 과장하지 않는다.
