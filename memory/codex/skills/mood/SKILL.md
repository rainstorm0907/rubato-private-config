# When to use

- `/mood`, `상담해줘`, `상담좀`, `감정 정리해줘`, `예은이랑`, `mood` 같은 표현이 보일 때
- 로컬 mood archive를 다시 읽어 현재 상태를 해석해야 할 때
- 일정표, 스크린샷, 최근 로그를 근거로 페이싱 조언이 필요할 때

쓰지 말 것:

- 코드 수정, 일반 문서 작업, 기술 디버깅
- 자해/학대/응급 정신건강 판단이 필요한 상황에서 전문 지원 대체용으로

# Inputs / context to gather

1. 먼저 현재 대화에서 사용자가 무엇을 원하는지 한 줄로 고정한다.
2. 현재 메모리의 `/Users/wooojin/.codex/memories/skills/mood/SKILL.md`와 live mood 작업에 쓰이는 `/Users/wooojin/.codex/skills/mood/SKILL.md`를 함께 확인한다.
3. 로컬 아카이브는 이 순서로 본다.
   - `/Users/wooojin/mood/counseling/system.md`
   - Woojin profile/logs
   - Yeeun profile/logs는 관계 맥락일 때만
   - `library/**`는 깊은 근거가 필요할 때만
4. 사용자가 `SKILL.md 수정했는데 다시 한번 말해줘`처럼 말하면 현재 skill 파일을 다시 읽는다.
5. 시간표/스크린샷이 있으면 제약의 증거로 취급한다.

# Procedure

1. 요청 유형을 분류한다.
   - 상태 해석
   - 관계/예은 맥락
   - 번아웃/학기 과부하
   - 짧은 정리 + 다음 액션
2. 확실한 사실과 반복 패턴만 먼저 적는다.
3. 불확실한 해석은 가설로 낮춰 말한다.
4. 답변 구조는 짧게 유지한다.
   - 지금 보이는 핵심 상태
   - 왜 그렇게 보이는지 근거
   - 오늘/이번 주에 할 작은 다음 액션 1개
5. 사용자가 지친 상태면 분석을 길게 끌지 말고 `덜 망가지게 버티기` 프레임으로 전환한다.
6. 사용자가 `하나도 버릴게없어` 같은 고정 제약을 말하면, 무엇을 포기할지보다 어느 카테고리의 기준을 낮출지 제안한다.
7. 관계 조언은 짧은 안심 문장과 낮은 죄책감 프레임을 우선한다.

# Efficiency plan

- archive 전체를 매번 다 읽지 말고, 먼저 최신 로그와 관련 인물 파일만 확인한다.
- 관계 맥락이 없으면 Yeeun 자료는 건너뛴다.
- 학기 과부하 패턴이 보이면 `버티기`, `지친`, `하나도 버릴게없어`, `시간표`, `쉬는 시간을 예약해야만 쉬는 구조`를 먼저 grep한다.
- 같은 턴 안에서 이미 본 파일은 다시 열지 말고 핵심 문구만 재사용한다.
- stop rule: 핵심 패턴과 작은 다음 액션이 나오면 추가 탐색보다 답변을 먼저 준다.

# Pitfalls and fixes

- 증상: 답이 추상적이고 길다.
  - 원인: 상태 해석을 길게 끌고 실천 단계로 못 넘어감.
  - 수정: 핵심 상태 1개 + 근거 + 작은 다음 액션 1개로 압축한다.
- 증상: `좀 쉬어` 같은 일반론이 나온다.
  - 원인: 고정 제약을 무시함.
  - 수정: 포기보다 기준 하향, 회복 슬롯 예약, category-based expectation management로 바꾼다.
- 증상: 지나치게 단정적이다.
  - 원인: low-confidence 가설을 사실처럼 말함.
  - 수정: 반복 로그 근거가 없으면 가설 표시를 유지한다.

# Verification checklist

- 현재 skill/아카이브를 다시 읽어야 하는 조건이 있었는지 확인했다.
- 답변이 진단처럼 단정하지 않는다.
- 사용자의 실제 표현이나 최근 증거를 최소 1개 이상 반영했다.
- 작은 다음 액션이 있다.
- 위기 대응이 필요한 상황이면 전문 지원 권고로 경계를 분명히 했다.
