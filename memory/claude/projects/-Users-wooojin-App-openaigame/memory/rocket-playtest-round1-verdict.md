2026-08-15 우진님 1차 직접 플레이 판정 (Fable vs Daybreak 비교):

- Fable v1(`experiments/fable-medium/`)이 압도적 우위. **동결된 기준점**: 저속 충돌 관대함, 모서리에서 살아나는 느낌, 바닥 반동, 이펙트, 중력 430의 무게감, 회전 반응, 여유 있는 맵 간격. v1 폴더는 비교 기준으로 수정 금지.
- 날개는 두 프로토타입 모두 실패. 실패 원리: 낙하 저항 과다 + 공중에서 기체를 붙잡고 정렬하는 자동화가 손맛을 죽임. **자동 측정의 "낙하 감소"를 재미 성공으로 해석하지 말 것** — 우진님 기준은 떨어지는 무게감 + 직접 자세를 만들어 빠져나오는 조작.
- 2차 시험(`experiments/fable-medium-v2/`): 날개 A안(속도 게이트) vs B안(받음각 게이트+실속), 1/2/3 즉시 전환. 자동 정렬·과도 저항 금지, 중력 무변경이 설계 제약.
- Daybreak 쪽 폴더/코드는 읽지도 섞지도 않는 것이 지속 규칙. Daybreak에서 채택한 발상은 플레이 중 값 조절 개발 화면뿐.

2026-08-15 2차 플레이 추가 판정 (v2): 우진님이 슬라이더로 직접 찾은 **첫 재미 기준값**을 v2 기본값으로 고정 — 중력 604, 추진 시작 764, 추진 최대 1400, 연료 총량 30, 회전 힘 11, 카메라 부드러움 9.36 (회전 감쇠는 v1 원본 5.5). 즉 v1의 중력 430 동결은 v2 기준값으로 대체됨(v1 폴더 자체는 계속 무수정). 날개는 A안(속도 게이트)이 그나마 낫지만 **다시 쓰고 싶은 날개는 아직 없음**.

**Why:** 이후 라운드에서 날개·부품을 다시 만질 때 같은 실패(자동 안정화 장치화)를 반복하지 않기 위한 기준.
**How to apply:** 부품 설계 시 "자동으로 문제를 없애는가, 숙련으로 열리는가"를 먼저 묻고, 자동 측정 수치를 재미 판정으로 승격하지 않는다.
