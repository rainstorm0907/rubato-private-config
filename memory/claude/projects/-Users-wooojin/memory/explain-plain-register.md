2026-08-12 세션에서 같은 교정 2회: "뭔소린지 도통 이해가 안되는데? 실제 maplog 개발에 어떻게 쓴다는거야", "좀 이해되게 말해봐". 둘 다 내 요약이 틀려서가 아니라 **밀도가 높아서** 나온 교정.

**Why:** 개념 라벨·표·계층 요약은 정보는 맞아도 우진님 입장에서 "그래서 뭘 한다는 건데"가 안 잡힘. 통한 방식은 본인 이력의 구체 사례(consult 패치 유실, 아침 compact 사고)와 생활 비유(정기점검, 옷장 정리)로 풀어쓴 버전.

**How to apply:** 검토 결과·설계 설명은 ① 실제로 뭐가 달라지는지 시나리오로 먼저, ② 전문용어는 한 번 풀어서, ③ 우진님이 겪은 사건을 예시로. 문서용 담백체([[woojin-writing-voice]])와는 별개 — 이건 대화 설명 레지스터. 관련: [[quiz-answers-no-explanation]](반대 극단: 퀴즈는 답만).

**[갱신 2026-08-12, 39일치 세션 전수 분석]** 이건 단발 교정이 아니라 7월부터 12개 이상 세션에서 반복된 우진님의 최상위 선호로 확인됨: "아니 이게 먼소리야 좀만 더 사람이 말하듯이"(7/29), "STATUS: COMPLETE 이런식으로 말하는거 좀 불편한데"(7/31), "내가 확정해야되는것들 좀 쉽게 말해줘. 이해가 안되잖아"(8/3·8/6). UI 설계에도 같은 원리를 요구함: "사람은 일일이 글을 읽지 않아. 직관은 구역·행동 우선순위로"(7/17~18, Maplog 리뷰 12세션).
