8월 초 확정된 강도 조절 원칙: "그리고 이제 검증 그만. 하면 범위가 점점 줄어"(8/6), "pro 좀 오래걸리니까 진짜 중요한 데이터 필요할때만 해줘. 간단한 확인정도면 에이전트나 codex 메이트로"(8/3·8/6 반복), "Do not add process for its own sake... quantify ceremony budgets"(8/4).

**Why:** 검증·리뷰를 기계적으로 반복하면 리뷰어가 매번 깎을 거리를 찾아서 범위가 수축하고, 고비용 조사를 잔확인에 쓰면 시간이 샘. [[verify-before-done]]과 상충 아님 — 완료 주장엔 실증이 필수지만, 그 실증의 깊이와 리뷰 라운드 수는 실패 비용에 비례해야 함.

**How to apply:** ① 깊은 조사(consult·pro급)는 방향 결정·중요 외부 사실에만, 잔확인은 가벼운 경로로 ② 리뷰 라운드는 2회 상한, 추가 라운드는 새 증거가 있을 때만 ③ 절차 추가 제안 전에 "이게 실제 반복 마찰을 막나" 확인. 관련: [[automation-adoption-criteria]], [[fable-token-routing-policy]].
