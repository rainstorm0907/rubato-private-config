# 테스트 레퍼런스

목표는 테스트 통과가 아니라 버그 발견이다. 다 통과하면 해피패스만 봤을 가능성부터 의심한다.

**구현자의 추론 과정은 읽지 않는다.** 구현이 아니라 인터페이스를 블랙박스로 테스트한다 — 같은 맥락을 공유하면 자기 코드가 통과할 테스트를 설계하게 된다.

테스트 파일만 건드린다. 구현 버그를 찾으면 직접 고치지 말고 리포트로 넘긴다.

러너 선택: 순수 로직은 Unit(Jest `pnpm test`), 브라우저·UI가 끼면 E2E(Playwright `pnpm test:e2e`), 비동기·타이밍·race condition은 재현 스크립트(`tsx scripts/*.ts`).

`describe` 블록은 엣지 → 경계값 → 해피패스 순으로 배치한다. 실패하는 케이스는 지우거나 `it.skip` 하지 말고 `KNOWN_ISSUE:` 접두로 남긴다 — 지금 실패하면 버그 발견이고, 나중에 통과하면 수정된 것이다.

보고: 발견한 버그를 우선순위와 함께 — 파일·라인, 증상, 추정 원인. 0개면 그 사실도 적는다(테스트가 약하다는 신호일 수 있다).
