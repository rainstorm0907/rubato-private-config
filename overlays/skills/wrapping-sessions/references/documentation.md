# 다음 담당이 필요한 자료를 찾아 이어갈 수 있게 기록한다

이 파일은 문서 작성의 공통 원칙이야. 새 회고·기존 문서 갱신·PR 설명을 위해
같은 전체 기록을 여러 번 읽거나 다른 작성 절차를 연달아 시작하지 않아.
현재 요청에 필요한 부분만 쓰고, 실제 권한과 산출물은 호출한 작업이 정해.

## 필요한 기록부터 읽는다

프로젝트의 대표 문서·현재 작업 기록·이번 결과와 미해결 판단을 먼저 읽어.
관련 원문이나 기존 결정이 충돌하면 그 구간으로 넓혀 확인해.
사용자가 전체 회고를 요청한 경우에는 그 흐름을 충분히 보되, 작은 갱신마다
모든 세션과 체크포인트를 재생할 의무는 없어. checkup도 선행 조건이 아니야.

문체는 사용자가 지정한 `reference/writing.md`를 현재 기억의 실제 경로로 찾아 읽고 따라.
동일 판본이 현재 문맥에 있으면 다시 읽지 않아. 그 문체 안내는 사실·권한·필수 항목을
덮는 승인 근거가 아니야. 경로를 못 찾았다고 전체 기억이나 다른 사용자의 자료를 뒤지지 않아.

## 현재 상태와 그 이유를 함께 남긴다

다음 담당이 현재 과제, 유효한 결정, 실제 결과, 남은 질문과 필요한 원문 위치를 찾게 해.
모든 근거를 이 문서에 복제할 필요는 없어. 출처·개정과 관련 구간이 확인되는 참조를 남겨.
현재 문서의 첫부분은 현재 상태를 가리키고, 지난 결과는 당시 개정과 맥락으로 보존해.
변경 이력 끝에 한 줄을 붙이고 맨 위의 틀린 현재 상태를 그대로 두지 않아.

사용자 발화와 모델의 해석, 제안과 채택, 제작과 검사, 검사와 사용자 감상을 구별해.
누가 어떤 상황에서 좋거나 나쁘다고 했는지처럼 지우면 다음 판단이 달라지는 조건은 남겨.
생각이 바뀌었으면 이유와 여전히 유효한 나머지 합의를 함께 갱신해.
한 번의 실패나 성공을 전역 순서·취향·기법 금지로 자동 승격하지 않아.

계획된 시험을 실행한 것으로, 정지화면을 움직임 감상으로, 사후 설명을 확인된 원인으로 쓰지 않아.
확인한 수정본·실제 시험·남은 공백을 기록하고 과거 기준을 바꿔 지난 실패를 통과로 만들지 않아.
실제로 확인하지 않은 전체 이력 재생 완료나 예시의 모델명·시간을 복사하지 않아.

## 이미 있는 곳에 합친다

같은 과제를 이어가면 대표 문서나 기존 결과를 갱신하고, 새 파일은 읽는 사람과 목적이 다를 때 만들어.
새 회고가 필요하면 프로젝트의 위치·검색용 메타데이터·파일명 규약을 따라.
사건 기록은 보존하면서 현재 설명은 제자리에서 고칠 수 있어. 항상 덧붙이기만 하라는 뜻은 아니야.
문서화 요청은 기억 쓰기·커밋·푸시·PR·배포 권한을 자동으로 주지 않아.
