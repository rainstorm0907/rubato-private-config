# browser-cli

브라우저 표면은 둘뿐이다. 나머지는 쓰지 않는다. 단, 브라우저가 필요 없는 공개
본문까지 억지로 브라우저에 태우지는 않는다.

## 브라우저를 열기 전 — 공개 읽기

결과가 **공개 본문·메타데이터**이고 뽑을 값이 이미 정해져 있으며 결과가 작을
것으로 예상될 때만 `insane-search`를 읽고 비브라우저 경로를 먼저 쓴다.
이 경로에서 `insane-search`는 플랫폼·의존성 참조문서일 뿐이고 실행면은
`isearch` 하나다. 그 문서의 raw `python3 -m engine` R1/R6는 `insane-search`
자체를 끝까지 수행하는 별도 작업에만 적용한다.

- X/Reddit/YouTube/GitHub처럼 공식 API, RSS, oEmbed, `yt-dlp` 경로가 이미 있는
  플랫폼도 개별 글·정확한 메타데이터처럼 좁은 조회에만 Phase 0을 먼저 쓴다.
  넓은 피드·검색 결과를 읽고 요약하는 작업은 원문이 이쪽 컨텍스트로 쏟아지므로
  `gbrowse`로 보낸다.
- 일반 공개 URL이 403/WAF에 막혔고 정확한 값이나 셀렉터를 이미 안다면, 전체 우회
  격자를 돌리기 전에 `isearch`로 Phase 0과 브라우저를 끈 generic transport 최대
  3회만 확인한다:

```bash
isearch "$URL"
isearch "$URL" --selector "article"
```

| code | 뜻 | 대응 |
|---|---|---|
| 0 | 4KB 이하의 검증된 공개 결과 | 그대로 사용 |
| 3 | `insane-search` 의존성 없음 | 그 스킬의 의존성 가드를 한 번 실행 |
| 5 | 출력이 4KB 상한 초과 | 아무것도 읽지 말고 `gbrowse` |
| 6 | 엔진 자체 오류 | trace를 확인하고 오류를 고침 |
| 7 | Phase 0과 generic transport 3회가 모두 실패 | 전수 격자·Playwright로 넓히지 말고 `gbrowse` |
| 8 | 404·인증·페이월 같은 terminal wall | 브라우저로 넓히지 말고 벽을 그대로 보고 |

`isearch`는 `insane-search`의 R6 전수 실패 지시를 호출자에게 내보내지 않는다.
실패와 과대 출력은 둘 다 브라우저 라우팅 결과로 바꾸고, 원문은 stdout에 찍지 않는다.

로그인 상태, 클릭·폼, 실제 렌더링, 스크린샷이 필요하면 이 탐색을 건너뛰고 처음부터
아래 브라우저 경로로 간다. 공개 페이지라도 읽어봐야 무엇이 중요한지 알 수 있으면
비브라우저 원문 덤프 대신 `gbrowse`로 간다.

## 라우팅 — 질문 하나

> **어디를 눌러야 할지, 어떤 값을 뽑을지 지금 이미 아는가?**

- **안다** → `abrowse '<js>'` (L1)
- **모른다 — 찾아야 하거나 읽고 판단해야 한다** → `gbrowse "미션"` (L2)

이 질문 하나가 "페이지 원문이 누구 컨텍스트에 떨어지나"를 결정한다. 스냅샷 트리를 출력해야 다음 판단이 서는 상황이면 그건 전부 L2다.

**애매하면 L2다.** "일단 L1으로 싸게 찔러보고 안 되면 올린다"는 반대로 간다 — 애매하다는 건 봐야 안다는 뜻이고, 보는 순간 원문이 이쪽 컨텍스트로 들어온다. `abrowse`의 4KB 상한이 그 시도를 막는 이유가 이것이다.

## L2 — `gbrowse` (기본값)

```bash
gbrowse "maplescouter.com 상단 네비 라벨 전부"
gbrowse -t 20 "..."   # 툴콜 예산 (기본 14)
gbrowse -v  "..."     # 툴콜 트레이스를 stderr로
```

grok이 Aside 브라우저를 몰고, 페이지 원문은 grok 컨텍스트에서 소모된다. 여기로는 최종 답만 온다.
실측: 단순 읽기 22초 / 1 브라우저콜 / $0.012, 클릭+탐색 106초 / 13콜 / $0.052.

stderr 감사줄은 모델의 말이 아니라 **스트림에서 뽑은 사실**이다. `3 browser calls (2 errored) last url about:blank` 는 브라우저가 실제로 뭘 돌려줬는지를 말한다. 답변 산문과 감사줄이 어긋나면 감사줄이 맞다.

**종료 코드가 판정이다. 출력을 눈으로 재해석하지 않는다.**

| code | 뜻 | 대응 |
|---|---|---|
| 0 | 최종 답변 | 그대로 사용 (답변 자체가 "로드 실패"일 수 있다 — 그건 정상 결과다) |
| 2 | 최종 답변 없음 | 미션을 쪼개서 재시도 |
| 3 | Aside 로그아웃 | `aside account login` |
| 4 | **툴을 한 번도 안 부르고 답함** | **버린다.** 기억으로 지어낸 답이다 |

exit 4가 왜 필요한가: 브라우저를 열지 않고도 `stopReason: end_turn` + 그럴듯한 답이 나온다. 실측으로 12초 만에 접속 불가 사이트의 h1을 자신 있게 답했고, 봉투만 보면 완벽히 정상이었다.

예산을 다 쓰면 같은 세션에 **딱 한 번** "본 것만으로 지금 답해라"를 넣고 `PARTIAL`로 내보낸다. 새 미션 자동 재제출은 하지 않는다.

미션 쓰는 법: 원하는 값과 멈출 지점을 한 문장에 넣는다. "전부", "빠짐없이" 같은 말은 예산을 태운다.

실측 상한이 106초라 단순 조회가 아니면 처음부터 백그라운드로 돌린다. 호출한
하네스의 foreground 대기창에 잘려도 grok은 계속 브라우저를 몰기 때문에, 답은 못
받고 탭만 남을 수 있다.

## L1 — `abrowse` (우진님 로그인 브라우저, 결정적 한 스텝)

```bash
abrowse 'const p = await openTab("https://x.com"); try { console.log(await p.evaluate(()=>location.href)); } finally { await closeTab(p); }'
abrowse -f step.js
abrowse -m 8000 '...'     # 상한을 의도적으로 올릴 때만
```

값을 이미 아는 조회, L2 답의 검증, 스크린샷·다운로드처럼 증거 자체가 필요할 때.

| code | 뜻 |
|---|---|
| 0 | 출력 |
| 3 | Aside 로그아웃 |
| 5 | **출력이 4KB 상한 초과 — 아무것도 안 찍고 종료** |
| 6 | REPL 스텝 자체가 에러 |

**exit 5가 라우팅 규칙 그 자체다.** "트리를 출력하지 마라"는 지시였지 가드가 아니었다. 이제 상한이 가드다 — 4KB를 넘겼다면 뽑을 값을 안다고 착각한 것이고, 그 작업은 `gbrowse`로 간다.

**`openTab` 직후 실제 URL을 확인한다.** 열기에 실패해도 예외를 던지지 않고 죽은 Page를 돌려준다. `page.url()`과 스냅샷 헤더의 `[url=...]`은 "열려고 했던 URL"이라 증거로 쓸 수 없다.

한 번의 `abrowse` 호출은 한 REPL 세션이다. 이어지는 스텝은 한 호출 안에 넣는다.

세부 API는 `aside-browser` 스킬을 본다.

## 예외 표면과 쓰지 않는 것

- **`aside exec`** — 타임아웃 플래그 없음, 진행 출력 없음(실측 459초 0바이트), 강제 종료하면 실행 기록이 통째로 사라져 사후 복구 불가, 열린 탭은 `closeTab()`도 `page.close()`도 성공을 보고하면서 실제로는 안 닫힌다. 우진님 로그인 세션·Aside 메모리·히스토리가 **반드시** 필요한 미션이 실제로 나올 때만 꺼내고, 그때도 백그라운드 + 외부 타임아웃 + `aside account status` 선점검.
- **`agent-browser`** — Aside와 무관한 격리 브라우저다. 이 라우터에서는 쓰지 않고, 사용자가 격리 브라우저를 명시한 별도 작업에만 쓴다.
- `browser-use`, `chrome-devtools` — 설치돼 있지 않다.

## 카나리

설정이 조용히 어긋나는 걸(툴 이름 변경, MCP 미로딩, 신뢰 경계) 잡는 가장 싼 검사:

```bash
gbrowse -t 8 "https://example.com 을 열어서 h1 텍스트를 알려줘"
```

**통과 = stderr 감사줄의 `browser calls`가 1 이상이고, 답이 감사줄의 실제 결과와
맞는 것.** 네트워크에 따라 `Example Domain`이나 로드 실패가 나올 수 있고 둘 다
정상이다. 브라우저 호출이 0이면 exit 4로 기각되어야 한다. 특정 사이트가 계속
막힌다는 가정은 카나리에 넣지 않는다.

결정적 REPL 경로는 따로 본다:

```bash
abrowse 'const p = await openTab("https://example.org"); try { console.log(await p.evaluate(()=>location.href), "|", await p.evaluate(()=>document.querySelector("h1").textContent)); } finally { await closeTab(p); }'
```

**통과 = `https://example.org/ | Example Domain`.** `about:blank`가 나오면 Aside 데몬이 죽었거나 재시작 중이다(`aside account status`로 확인). 둘 다 통과해야 설정이 온전한 것이다.

`gbrowse` 카나리는 유령 탭을 남길 수 있지만 화면에는 안 보이고 시간이 지나면 사라진다(아래 위생). 매 세션 돌릴 일은 아니고, 어긋난 정황이 있을 때 — 답이 수상하게 빠르거나, 감사줄이 브라우저콜 0을 찍거나, Aside를 업데이트한 뒤 — 꺼내 쓴다.

## 위생

**동시 실행 금지.** `gbrowse` 두 개를 동시에 돌리면 하나의 Aside 브라우저를 나눠 쓴다. 한쪽이 연 탭을 다른 쪽이 `page`로 잡고, 탭 목록 기준선이 서로 오염된다. 병렬이 필요하면 미션을 하나로 합친다.

**연 탭은 같은 호출 안에서 닫는다.** 로드에 성공한 탭이면 `closeTab(p)`가 정확히 동작한다(실측: 11 → openTab 12 → closeTab 11, 흔적 없음). 실제로 브라우저 UI에 뜨는 탭이라 안 닫으면 우진님 화면에 그대로 쌓인다.

**로드에 실패한 페이지는 유령을 남기고, 그건 누구도 못 치운다.** `listBrowserTabs()`에는 잡히지만 Aside 사이드바에는 없고, `closeTab`을 불러도 개수가 안 줄어든다(실측: 9개 대상으로 호출, 4초 후에도 그대로). 목록에는 `https://example.com/`처럼 **열려던 주소**로 표시되므로 `about:blank`로 걸러낼 수도 없다. 시간이 지나면 알아서 줄어든다(실측: 손대지 않았는데 13 → 11).

그래서 `listBrowserTabs().length`는 경보 지표로 쓸 수 없다 — 아무도 만들지 않은 유령이 숫자를 부풀린다. 지킬 건 하나뿐이다: **내가 연 탭은 내가 닫는다.** 우진님께 정리를 요청해야 할 상황은, 목록이 아니라 브라우저 화면에 실제로 탭이 쌓여 있을 때다.

## 이 설계가 선 근거

1. **희소 자원은 컨텍스트만이 아니라 "돌아오는 증거"다.** 덩어리를 grok 쪽에서 태우는 건 절반이고, 나머지 절반은 브라우저를 실제로 거쳤다는 사실이 산문이 아닌 형태로 함께 건너오는 것이다. 감사줄이 그 절반을 담당한다.
2. **모델은 가장 싼 경로를 택한다.** "모르는 건 지어내지 마라"를 시스템 프롬프트에 넣어도 행동이 안 바뀌었다. 바뀐 건 싼 경로를 없앴을 때다 — 터미널·파일 툴을 실제로 차단하고 브라우저만 남기자, 같은 미션에서 지어내는 대신 "openTab 후 href가 about:blank, 로드 실패"라고 정확히 보고했다. 그래도 툴콜 0회 기각은 남긴다. 지시는 가드가 아니고, 화이트리스트가 가드다.
3. **최종 답은 마지막 툴콜 이후의 텍스트다.** grok의 `.text` 필드는 모든 어시스턴트 턴을 이어붙인 것이라 내레이션이 답 앞에 섞인다. `--json-schema`로 막으려 하면 첫 턴 내레이션이 최종 출력으로 확정돼 런이 조기 종료된다. streaming 출력에서 툴콜 경계로 자르는 것만이 구조적으로 옳다.
4. **예산이 없으면 완벽주의로 소진한다.** 예산을 알려주지 않았을 때, 답을 이미 손에 쥔 뒤로 8턴을 툴팁 호버에 썼다. 예산 고지 + "같은 단계 두 번 실패하면 우회" + 소진 시 1회 마무리가 이걸 막는다.
